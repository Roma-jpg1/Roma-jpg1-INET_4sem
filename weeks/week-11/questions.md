# Вопросы для самопроверки

1. Зачем создавать пользовательскую сеть (bridge network) в Docker Compose, если есть дефолтная?
   Пользовательская сеть даёт лучший контроль: можно явно задавать имена, изоляцию, правила доступа между сервисами и использовать несколько сетей. Дефолтная создаётся автоматически, но менее гибкая.

2. В чем разница между `build` и `image` в описании сервиса?
   `build` — собирает образ из Dockerfile, `image` — использует уже готовый образ (локальный или из registry).

3. Что делает `depends_on`? Гарантирует ли он, что приложение в зависимом контейнере полностью инициализировалось?
   Он управляет порядком запуска контейнеров, но не гарантирует, что сервис внутри контейнера полностью готов к работе.

4. Как работают healthcheck-и и как использовать их в `depends_on`?
   Healthcheck проверяет состояние контейнера (healthy/unhealthy). В `depends_on` можно указать условие `service_healthy`, чтобы запуск происходил только после успешного healthcheck.

5. Как передать переменные окружения в контейнер через Compose (минимум 2 способа)?
   Через `environment` в compose-файле и через `.env` файл (или `env_file`).

6. Почему Docker Compose редко используют в продакшене (хотя это возможно)?
   Он не предназначен для масштабирования, отказоустойчивости и управления кластером — для этого используют Kubernetes или Docker Swarm.
