# Вопросы для самопроверки

1. Что такое слой в Docker и почему порядок команд в Dockerfile важен для кэширования?
2. В чем суть Multi-stage build? Какие проблемы он решает?
3. Зачем нужен файл `.dockerignore`?
4. Чем отличаются инструкции `CMD` и `ENTRYPOINT`?
5. Почему рекомендуется использовать `COPY` вместо `ADD`?
6. Почему приложение в контейнере должно слушать `0.0.0.0`, а не `127.0.0.1`?



1. Слой (layer) в Docker — неизменяемый слой файловой системы, создаваемый каждой инструкцией в Dockerfile (RUN, COPY и т.д.).
    Порядок важен, потому что Docker кэширует слои: если изменится одна команда, все последующие пересоберутся.

2. Multi-stage build — сборка в несколько этапов с использованием нескольких FROM.
   Позволяет оставить в финальном образе только нужные файлы, уменьшить размер и убрать лишние зависимости (например, компиляторы).

3. .dockerignore — файл, который исключает ненужные файлы из контекста сборки.
   Ускоряет сборку и уменьшает размер образа (например, исключает node_modules, .git).

4. CMD vs ENTRYPOINT:
   CMD — команда по умолчанию (можно переопределить)
   ENTRYPOINT — основной исполняемый процесс (сложнее переопределить)

5. Почему COPY лучше ADD:
   COPY проще и предсказуемее.
   ADD имеет дополнительные функции (распаковка архивов, загрузка URL), что может приводить к неожиданному поведению.

6. Почему слушать 0.0.0.0, а не 127.0.0.1:
   127.0.0.1 доступен только внутри контейнера.
   0.0.0.0 позволяет принимать подключения извне (например, с хоста).
