# Вопросы для самопроверки

1. Зачем нужен файл `.proto`? Почему мы не пишем классы сообщений сразу на Python?
2. Что такое Unary RPC? Чем он концептуально похож на REST запрос?
3. Почему gRPC обычно эффективнее REST (JSON) по процессору и трафику?
4. Что такое "обратная совместимость" в Protobuf и зачем нужны номера полей (тэги, например `= 1`)?
5. Что такое Stub (стаб) на клиенте и Servicer на сервере?
6. В каких случаях вы бы выбрали REST, а в каких — gRPC?


1. .proto нужен для описания контракта (сервисы, методы, сообщения). Он позволяет генерировать код и обеспечивает одинаковое понимание API клиентом и сервером. Если писать сразу на Python — не будет универсальности и автогенерации для других языков.
2. Unary RPC — это один запрос и один ответ. Концептуально похож на обычный REST-запрос (один HTTP-запрос → один ответ).
gRPC эффективнее, потому что использует бинарный формат (Protobuf), который меньше по размеру и быстрее обрабатывается, чем JSON.
3. Обратная совместимость — это возможность старых и новых версий работать вместе. Номера полей (= 1) — это идентификаторы полей в бинарном формате, их нельзя менять, чтобы не ломать совместимость.
4. Stub — это клиентская часть, через которую вызываются методы сервера как обычные функции. Servicer — это серверная реализация этих методов.
5. REST — когда нужен простой, понятный, публичный API (например для веба). gRPC — когда важны скорость, производительность и взаимодействие между сервисами.
