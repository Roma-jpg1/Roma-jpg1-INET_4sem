# Вопросы для самопроверки

1. Зачем нужны variables в GraphQL запросе? Почему нельзя просто склеивать строки?
   variables позволяют безопасно передавать данные, избегать инъекций и переиспользовать один и тот же запрос. Склеивание строк небезопасно и неудобно.

2. Из каких полей состоит стандартный JSON-запрос к GraphQL серверу?
   query, variables (опционально), operationName (опционально).

3. Почему у GraphQL обычно только один URL endpoint?
   потому что все действия описываются внутри запроса, а не через разные URL как в REST.

4. Что означает наличие поля errors в ответе сервера? Может ли оно прийти вместе с data?
   errors означает, что произошла ошибка. Да, может прийти вместе с data (частичный ответ).

5. Как клиент должен обрабатывать ошибки, если HTTP статус ответа 200?
   нужно проверять поле errors в JSON и обрабатывать его, даже если статус 200.

6. В чем плюсы использования типизированных клиентов (например, Apollo Client или Relay) перед простыми HTTP-запросами?
   они дают автодополнение, проверку типов, кэширование, удобную работу с состоянием и уменьшают количество ошибок.
